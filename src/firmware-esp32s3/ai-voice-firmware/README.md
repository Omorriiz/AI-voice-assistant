# Нильс: прошивка голосового ассистента (ESP32-S3)

Устройство постоянно слушает микрофон и ждёт ключевое слово **«Привет ESP»**. Слово распознаётся
прямо на ESP32: пока оно не прозвучало, на сервер ничего не отправляется. Кнопка больше не нужна.

## Как это работает

1. ESP32 слушает микрофон INMP441 и ищет «Привет ESP». Используется модель `wn10_ru_privetesp`
   из библиотеки Espressif esp-sr.
2. Слово услышано: короткий высокий сигнал, начинается запись команды.
3. Пауза в речи около 0,7 с: запись заканчивается и отправляется на сервер.
4. Ответ сервера играет через усилитель MAX98357A.
5. Снова ожидание «Привет ESP».

Если после ключевого слова ничего не сказать за 6 секунд, прозвучит низкий сигнал, и устройство
вернётся к ожиданию. Во время ответа ключевое слово не слушается, поэтому динамик не может сам себя
«разбудить».

## Оборудование

| Компонент | Подключение |
|---|---|
| Плата | ESP32-S3 DevKitC-1 **N16R8** (16 MB flash, 8 MB PSRAM): PSRAM обязательна для esp-sr |
| Микрофон INMP441 | BCK = GPIO17, WS = GPIO18, SD = GPIO16, L/R → GND, VDD → 3.3 V |
| Усилитель MAX98357A | BCLK = GPIO5, LRC = GPIO6, DIN = GPIO7 |

Пины задаются в `include/config.h` (`I2S_MIC_*`, `I2S_AMP_*`).

## Структура проекта

```
platformio.ini        настройки PlatformIO (фреймворк ESP-IDF)
flash_models.py       упаковка и прошивка модели «Привет ESP» (запускается автоматически)
partitions.csv        разделы flash: приложение 6 MB + модели 8 MB (раздел "model" по адресу 0x610000)
sdkconfig.defaults    настройки ESP-IDF: PSRAM, кэш, выбор модели «Привет ESP»
include/config.h      Wi-Fi, сервер, пины
main/main.c           прошивка
main/idf_component.yml  зависимости: esp-sr, esp_websocket_client
legacy/               прежняя Arduino-прошивка с кнопкой (не собирается, только для справки)
```

## Установка и прошивка (VS Code + PlatformIO)

Отдельно устанавливать ESP-IDF не нужно: PlatformIO скачает его сам (платформа
`espressif32 @ ^6.10.0`, ESP-IDF 5.4).

1. Откройте папку `ai-voice-firmware` в VS Code с расширением PlatformIO.
2. Проверьте `include/config.h`: Wi-Fi, IP сервера, пины.
3. Подключите плату к порту **UART** (тот, что работал раньше, COM5).
4. Соберите и прошейте: **PlatformIO → Upload**, или в терминале:

   ```
   pio run -t upload
   ```

   Первая сборка идёт долго, несколько минут: скачиваются ESP-IDF, esp-sr и WebSocket-клиент.
   После прошивки приложения скрипт `flash_models.py` сам собирает `srmodels.bin` и записывает его
   в раздел `model`. В логе это строки с `[models]`.
5. Откройте монитор порта:

   ```
   pio device monitor
   ```

   При старте прозвучит короткий сигнал, затем в логе появится `Слушаю. Скажите «Привет ESP»`.

**Прошить только модель**, без приложения: `pio run -t flash_models`.

**Скорость прошивки.** В `platformio.ini` стоит `upload_speed = 115200`, как было раньше: надёжно, но
модель пишется долго. Если плата прошивается стабильно, поставьте `460800` или `921600`.

### Почему ESP-IDF, а не Arduino

Ключевое слово «Привет ESP» есть только в новейшей версии esp-sr. Его выбор и упаковка модели
делаются в настройках ESP-IDF (`sdkconfig.defaults`), которых нет в обычном Arduino-проекте. Сборка
под PlatformIO пропускает шаг упаковки модели esp-sr, поэтому его выполняет `flash_models.py`.

### Альтернатива: idf.py

Тот же проект собирается и чистым ESP-IDF 5.x, **не 6.x** (например, через Espressif Installation Manager:
`winget install Espressif.EIM-CLI`, затем `eim wizard`, версия v5.5.x). В терминале ESP-IDF:

```
idf.py set-target esp32s3
idf.py build
idf.py -p COM5 flash monitor
```

`idf.py flash` прошивает модель сам, скрипт не нужен.

## Настройки

| Где | Параметр | Что делает |
|---|---|---|
| `main/main.c` | `VAD_END_SILENCE_MS` (700) | Длина паузы, после которой команда считается законченной |
| `main/main.c` | `NO_SPEECH_TIMEOUT_MS` (6000) | Сколько ждать команду после ключевого слова |
| `main/main.c` | `DET_MODE_90` в `afe_init()` | Чувствительность ключевого слова. `DET_MODE_95` срабатывает легче, но чаще ложно |
| `include/config.h` | `MIC_SHIFT` (14) | Усиление микрофона: меньше число = громче |
| `include/config.h` | `MIC_USE_RIGHT_CHANNEL` | Если L/R пин INMP441 на 3.3 V |
| `include/config.h` | `MAX_RECORD_SECONDS` (10) | Максимальная длина команды |

## Протокол сервера (не изменился)

Устройство → сервер, после окончания команды:
`start_recording` → `audio_chunk` (`index`, `data` = base64) × N → `stop_recording`

Сервер → устройство: `hello`, `text_response`, `audio_response_start`,
`audio_response_chunk` (`data` = base64), `audio_response_end`

Аудио в обе стороны: **PCM16, моно, 16 кГц, little-endian, без заголовка WAV**. MP3 не поддерживается.
Ответ TTS с другой частотой (например, 24 кГц) сервер должен пересчитать в 16 кГц, иначе голос будет
медленным и низким.

## Если что-то не работает

| Сообщение в логе / симптом | Что делать |
|---|---|
| `Модели esp-sr не найдены в разделе "model"` | Модель не прошита: `pio run -t flash_models` |
| `Модель wn10_ru_privetesp не найдена` | В `sdkconfig.esp32-s3-devkitc-1` нет `CONFIG_SR_WN_WN10_RU_PRIVETESP=y`: удалите этот файл (он пересоздастся из `sdkconfig.defaults`) и пересоберите |
| `[models] esp-sr не найден в managed_components` | Сначала соберите проект (`pio run`), потом прошивайте |
| Ошибка сборки про версию ESP-IDF | Нужен ESP-IDF 5.3–5.x. Проверьте `platform` в `platformio.ini` |
| Слово не распознаётся | Говорите чётко, 0,5–2 м от микрофона. Попробуйте `DET_MODE_95` или `MIC_SHIFT 13` |
| Срабатывает само | Верните `DET_MODE_90`, уменьшите усиление (`MIC_SHIFT 15`) |
| Команда обрезается | Увеличьте `VAD_END_SILENCE_MS` (например, 1000) |
| `Ключевое слово услышано, но сервер не подключён` | Проверьте, что сервер запущен и `WS_SERVER_IP` / порт / путь верны |

После изменения `sdkconfig.defaults` удалите `sdkconfig.esp32-s3-devkitc-1`, чтобы настройки применились.
